# Week 2 Day 4 — CrewAI: Multi-Agent Collaboration, Roles & Task Delegation

A small CrewAI crew that reviews a sales dataset, generates business insights, and writes a
stakeholder-ready summary — built two ways (`Process.sequential` and `Process.hierarchical`) so the
two approaches can be compared head-to-head on quality, latency, and cost.

## Business task

> Review a sales dataset, generate business insights, and write a stakeholder-ready summary.

This mirrors how a data team splits work across specialists: one person profiles the data, one
turns numbers into insights, one writes it up for a non-technical audience. A small 9-row sample
sales CSV (`month`, `region`, `product`, `units_sold`, `revenue`) is generated by the notebook
itself, so it runs end-to-end with no external file needed.

## Agents

| Agent | Role | Tools |
|---|---|---|
| **Data Analyst** | Reads the raw CSV, produces a verified statistical profile (totals/trends by month, region, product; flags anomalies) | `FileReadTool` |
| **Business Insight Generator** | Interprets the profile into 3–5 business-relevant insights with likely causes | none — works only from the analyst's output |
| **Stakeholder Report Writer** | Turns the insights into a concise, non-technical executive summary with recommended actions | none — pure writing task |
| **Analytics Team Manager** *(hierarchical run only)* | Delegates to the right specialist and reviews each hand-off before passing it on | none — `allow_delegation=True` |

Tool access is kept role-appropriate: only the Analyst touches raw data, so the other agents can't
silently re-derive different numbers from the file.

All agents share one LLM config: `gemini/gemini-3.5-flash-lite` at `temperature=0.3`. Embeddings
are also pointed at Gemini so no `OPENAI_API_KEY` is required anywhere.

## Pipeline

```
Data Analyst  →  Insight Generator  →  Report Writer
 (JSON profile)   (numbered insights)   (markdown summary)
```

Each `Task` carries `context=[...]` pointing at the previous task so outputs chain through the crew.

**Format-mismatch fix:** an early run had the analyst prefacing its JSON with a stray sentence
("Here is the profile:"), which broke the Insight Generator's parsing. Fixed by tightening
`expected_output` to *"Return ONLY the JSON, no prose around it"* — formatting constraints belong
in `expected_output`, not `description`, since that's what the agent checks its final answer
against.

## Sequential vs. Hierarchical

| Aspect | Sequential | Hierarchical |
|---|---|---|
| Quality | Consistent, predictable hand-offs | Can catch/fix a bad hand-off via manager review |
| Latency / cost | Lower — no manager overhead | Higher — manager adds extra LLM calls per step |
| Reliability | Fails silently if one agent's output is malformed | More robust — manager can request a redo |
| Best for | Well-defined, low-ambiguity pipelines | Tasks needing quality control / dynamic delegation |

### Measured results (from the notebook's own run)

| Run | Wall-clock time | Total tokens | Requests | Approx. cost |
|---|---|---|---|---|
| Sequential | 50.6 s | 9,825 | 12 | $0.00782 |
| Hierarchical | 373.9 s (~6.2 min) | 170,096 | 112 | $0.11834 |

The hierarchical run used ~17x the tokens and ~15x the cost of the sequential run for the same
underlying task, driven by the manager's extra delegation/review round-trips.

## Success criteria

1. **Factual grounding** — every number in the final report traces back to the analyst's JSON profile.
2. **Completeness** — report covers month, region, and product trends, not just one dimension.
3. **Tone** — report reads as non-technical/executive-friendly, under 300 words.

The notebook prints a manual scoring sheet (1–5 per criterion) for each run — fill it in after
reading the printed output.

## Setup

```bash
# 1. (recommended) create a virtual environment
python3 -m venv venv && source venv/bin/activate

# 2. install dependencies
pip install crewai crewai-tools nest_asyncio --break-system-packages

# 3. get a free Gemini API key
#    https://aistudio.google.com/apikey
#    (this is the only key needed — no OPENAI_API_KEY required)

# 4. set it as an environment variable
export GEMINI_API_KEY="your-key-here"

# 5. run the notebook
jupyter notebook week2_day4.ipynb   # Cell → Run All
```

The first code cell calls `nest_asyncio.apply()` — required because `crew.kickoff_async()`
otherwise conflicts with Jupyter's own event loop.

Expect ~51s / $0.008 for the sequential run and ~6 minutes / $0.12 for the hierarchical run.
